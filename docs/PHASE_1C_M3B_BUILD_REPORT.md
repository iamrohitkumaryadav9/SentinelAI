## 2. Architecture

```text
kernel tracepoints (tp_btf, CO-RE)
  └─ sentinel.bpf.c ── extracts pid / cgroup / netns / vector / reason
       └─ sentinel_core.h handlers ── bounded per-CPU aggregation in maps (no ring buffer, no per-event output)
            └─ sentinel_loader (libbpf 1.4, skeleton) ── on request "s": one JSON line of CUMULATIVE counters
                 └─ sentinelai.ebpf.ProcessEbpfSource ── child process, bounded, read timeout
                      └─ sentinelai.collectors.ebpf ── strict parse → tick observations (counters)
                           └─ M3A normalize/snapshot ── deltas, rates, quantiles, coverage, quality, baseline
                                └─ EvidenceSnapshot (Pydantic-validated) ── M2 (unchanged) diagnoses
```

- **No diagnosis below M2.** BPF and loader code count and time events. The collector computes the contract quantities. Static tests prove that no label, rule threshold, reason set, rule-engine import or evidence item appears in the M3B code.
- **One handler implementation.** `sentinel_core.h` is the code the kernel runs. The replay harness compiles the same file with bounded arrays in place of maps, so fixture tests exercise the real correlation logic.
- **Pull, not push.** The loader answers each tick's request synchronously, so eBPF counters line up with the M3A tick clock and nothing is queued.

## 3. The four features

| Feature | Tracepoints | Scope / qualifier | Unit, aggregation | Computation |
|---|---|---|---|---|
| `sched.latency_hist.target` | `sched_wakeup`, `sched_wakeup_new` → `sched_switch` | `cgroup:<path>` (target subtree) | ms; **P50 and P99 as two measurements with distinct ids** (M3B-C1) | Nearest-rank quantile of the window's merged latency histogram |
| `softirq.exec_time.percpu` | `softirq_entry` → `softirq_exit` | `cpu:N`, `vector` ∈ the 10 kernel vectors | cores (CPU-s/s); RATE | Σ(exit − entry) ns over W ÷ Δt, per CPU × vector |
| `tcp.retrans_skb_rate` | `tcp_retransmit_skb` | `netns:<target>` | events/s; RATE | Retransmitted **skbs** per second in the target netns |
| `net.drop.kfree_skb` | `kfree_skb` | `netns:<target>`, `reason` | packets/s; RATE | Events per second per kernel drop reason in the target netns |

Exact tracepoint signatures were verified in this kernel's BTF (`btf_trace_*` typedefs):
`sched_wakeup(struct task_struct *)`, `sched_wakeup_new(struct task_struct *)`, `sched_switch(bool, struct task_struct *prev, struct task_struct *next, unsigned int)`, `softirq_entry/exit(unsigned int vec_nr)`, `tcp_retransmit_skb(const struct sock *, const struct sk_buff *)`, `kfree_skb(struct sk_buff *, void *location, enum skb_drop_reason)`. `NR_SOFTIRQS = 10`, `SKB_DROP_REASON_MAX = 95`.

## 4. Map and buffer design (all bounded, preallocated)

| Map | Type | Entries | Content |
|---|---|---|---|
| `sn_wake` | LRU_HASH | 16384 | Pending target wakeups: tid → (ts, cpu). The **only** per-task state; LRU-bounded. |
| `sn_hist` | PERCPU_ARRAY | 1 | 528-bucket log-linear latency histogram |
| `sn_stats` | PERCPU_ARRAY | 22 | Self-observation counters (matched, stale, repeat, unattributed, …) |
| `sn_sirq_start` | PERCPU_ARRAY | 1 | Pending softirq entry of this CPU |
| `sn_sirq_acc` | PERCPU_ARRAY | 10 | Cumulative ns and count per vector |
| `sn_retrans` | PERCPU_ARRAY | 1 | Target-netns retransmitted skbs |
| `sn_kfree` | PERCPU_ARRAY | 129 | Per drop-reason counts (128 core slots + 1 overflow slot) |

**Histogram:** values below 16 ns are exact. Above that, 16 sub-buckets per power of two (bucket width ≤ 1/16 of the octave), up to 2³⁶ ns. Bucket arithmetic is mirrored in Python, and the tests prove C and Python agree at boundary values and that buckets are contiguous.

**Userspace bounds:**
- the loader has a 64-byte request buffer and no queue, and exits at `--max-seconds` (≤ 86400), on stdin EOF/`q`, or on SIGINT/SIGTERM;
- the Python boundary allows one outstanding request, uses a read timeout, and caps line length (`MAX_LINE`), so oversized output is dropped rather than buffered (tested).

## 5. Scheduler correlation semantics

- **wakeup** (target subtree, tid ≠ 0): stored with `BPF_NOEXIST`, so a repeated wakeup keeps the **earliest** timestamp (`wake_repeat`).
- **wakeup_new**: always replaces. A new task never inherits an entry left by an earlier holder of the same tid (`wake_new_replaced`).
- **switch prev → next:**
  1. prev's pending entry is **cancelled**. A wakeup that found the task still running (`ttwu_runnable`) did not make it wait; without this, the task's next latency would be measured from a stale timestamp (`wake_cancelled_running`).
  2. If next has an entry, latency = now − ts is recorded, unless it is negative (`lat_negative`) or above the stale cut-off of 10 s (`lat_stale`).
  3. A switch-in without an entry (preempted task re-run, non-target task, evicted entry) records nothing. Only wakeup → switch is measured, as the contract locator states; preemption re-queue time is not included.
- **Migration:** the timestamp is global `CLOCK_MONOTONIC`, so cross-CPU latency is valid (`lat_migrated`).
- **Idle task:** tid 0 (every CPU's idle task) is never correlated.
- **Task exit:** a task that exits without running leaves an entry that is LRU-evicted or replaced by the next `wakeup_new` of that tid.
- **Target membership:** the task's cgroup v2 ancestor at the target's depth (`cgroup->ancestors[level]`) has the target's kernfs id. This covers the target and its descendants.
- **Not an interpretation:** high scheduler delay is not turned into "throttling" or any other cause.

## 6. Softirq accounting semantics

- One pending entry per CPU (softirqs do not nest on a CPU). Exit with the same vector adds (exit − entry) to that CPU × vector.
- Robustness counters: exit without entry, vector mismatch, entry overwritten (lost exit), invalid vector (≥ 10), negative or stale duration (> 1 s). None of these adds time.
- All ten vectors are measured, each as its own measurement (`vector` qualifier). **Network softirq time is NET_RX and NET_TX only.** TIMER, RCU and the rest are distinct measurements and are never summed into or reported as network time (tested). Softirq time is not equated with application CPU time.

## 7. TCP retransmission semantics

- One event per `tcp_retransmit_skb`, counted only when the socket's netns (`sk->__sk_common.skc_net.net->ns.inum`) is the target netns. Events in other namespaces and unattributable events are counted separately and never reported as target evidence.
- The unit is `events_per_second`; the locator states "one per retransmitted skb, not segments". It is never emitted as `tcp.retrans_rate`, the /proc RetransSegs segments/s feature, which remains a separate PROC measurement (tested side by side).

## 8. kfree_skb reason semantics

- **Netns attribution:** `skb->dev`'s namespace, else `skb->sk`'s; neither → unattributed (not target evidence).
- **Reasons are preserved, never interpreted:**
  - core values < 128 are counted per value;
  - subsystem reasons (high bits set) go to a single overflow slot, reported as `UNKNOWN_OVERFLOW`;
  - names come from the **running kernel's BTF** (`enum skb_drop_reason`, prefix stripped), so `NOT_SPECIFIED`, `QDISC_DROP`, `TCP_CSUM` and the rest stay distinct (tested);
  - an unnamed core value would be `UNKNOWN_<n>`.
- `NOT_SPECIFIED` is reported as observed. What a reason means for packet loss is decided only by M2 (`KFREE_REASONS_LOSS`, unchanged).
- A measurement exists only for reasons that occurred during the run. No zero-rate measurement is invented for the ~95 unseen reasons.

## 14. Observer overhead

**NOT YET MEASURED.** Measuring it requires loading and attaching the programs. Design choices aimed at the < 5 %-of-one-core target:
- in-kernel aggregation only, with no ring buffer and no per-event userspace work;
- per event, a constant number of map operations;
- `sched_switch`, the hottest path, does one delete and one lookup in a hash that holds only target tasks;
- the loader reads maps once per tick.

## 15. Known limitations (actual)

1. **Runtime unvalidated.** The verifier has not seen the programs, nothing has been attached, and no real kernel evidence exists yet. K1–K4, the lab and overhead belong to the privileged validation phase.
2. **Kernel-side field extraction** (pid, cgroup ancestor, netns reads) cannot be exercised by fixtures. It is covered by CO-RE resolution against this kernel (§10), by static assertions on the source, and by mutants K1–K5. It must be confirmed at runtime.
3. **Latency resolution:** quantiles are reported as the upper edge of the bucket holding the nearest-rank sample. That never underestimates, and overestimates by at most one bucket width (≤ 1/16 of the octave, about 6.25 %).
4. **Latency scope:** wakeup → switch only (the contract locator). Run-queue time after involuntary preemption is not included.
5. **kfree attribution:** an skb with neither `dev` nor `sk` is unattributable and is not counted as target evidence (it appears in `kfree_unattributed`).
6. **Per-CPU counters are incremented non-atomically.** A program nested on the same CPU (NMI) could rarely lose an increment. This was accepted for overhead.
7. **Pending-wakeup map at capacity:** when 16384 target tasks have pending wakeups at once, LRU eviction drops the oldest entry; its latency is not recorded. Eviction is not counted (an LRU limitation).
8. **M2 input:** `net.drop.kfree_skb` was already an M2 input (supporting predicates, with `NOT_SPECIFIED` at most WEAK). Once the loader runs, M2 will receive measurements it previously never had. The rules are unchanged; their effect on real snapshots is for the validation phase to observe.
9. **Build path:** the libbpf archive path is tied to the installed kernel-headers package (`KREL`). A kernel-headers upgrade requires setting `KREL`/`LIBBPF_DIR`, and the build refuses to proceed otherwise.
